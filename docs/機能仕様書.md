# EPUB読み上げアプリ 機能仕様書（検討版）

作成日: 2026-07-02
ステータス: **実装前レビュー待ち**

## 1. コンセプト

手持ちのEPUB（日本語書籍）を取り込み、VOICEVOXの音声でAudibleのように聴けるアプリ。
個人利用を前提とする。

---

## 2. VOICEVOX API 調査結果（2026-07-02 実測済み）

su-shiki版 VOICEVOX Web API（https://voicevox.su-shiki.com/su-shikiapis/）

| 項目 | 内容 |
|---|---|
| 合成エンドポイント | `https://deprecatedapis.tts.quest/v2/voicevox/audio/` |
| 方式 | 同期。リクエストするとWAVがそのまま返る（実測: 24kHz/16bit/mono, `audio/x-wav`） |
| パラメータ | `text`(必須), `key`(必須), `speaker`, `speed`, `pitch`, `intonationScale` |
| 話者一覧 | `https://deprecatedapis.tts.quest/v2/voicevox/speakers/?key=...`（JSON、動作確認済み） |
| ポイント確認 | `https://deprecatedapis.tts.quest/v2/api/?key=...` |
| ポイント消費 | **1リクエスト = 1500 + 100 × UTF-8文字数** |
| 保有ポイント | 約1,000万pt / **24時間ごとにリセット**（実測） |
| 注意 | APIキーはPOSTで送るのが推奨。個人利用想定のサービス |

### 2.1 ポイント制約から導かれる設計方針

- 1日あたり合成できるのは **約9万文字 ≒ 音声4〜5時間分**（150文字チャンクの場合: 16,500pt/回 × 約600回）
- 一般的な文庫本1冊は10〜30万文字 → **1冊まるごと事前合成は1〜3日に分割が必要**
- 聴きながら先読み合成する方式なら、1時間の再生 ≒ 2.5万文字 ≒ 280万pt で十分収まる
- **→ 合成済み音声は必ずローカルにキャッシュし、同じ箇所を二度合成しない**ことが最重要
- 再生速度変更はAPIの `speed` ではなく**プレイヤー側のレート変更**で行う（APIパラメータを変えるとキャッシュが無効になるため。プレイヤー側ならピッチ維持の変速が可能で、ポイントも消費しない）

### 2.2 APIキーの扱い

- キーはソースコードに直書きせず、設定ファイル/環境変数に置く（リポジトリを公開する場合に備える）
- アプリ内に残ポイント表示を設け、枯渇時は「本日の合成上限に達しました」と案内

## 3. 機能一覧

### 3.1 MVP（最初に作る範囲）

| # | 機能 | 内容 |
|---|---|---|
| F1 | EPUB取り込み | ファイル選択でEPUBをインポート。書名・著者・カバー画像・目次・本文を抽出して保存 |
| F2 | ライブラリ画面 | 取り込んだ本の一覧（カバー、書名、進捗%）。タップで再生画面へ。削除可 |
| F3 | 再生/停止/再開 | 文単位で合成した音声を連続再生。停止位置を記憶し、次回そこから再開 |
| F4 | バックグラウンド再生 | 画面オフ/他アプリ使用中も再生継続。ロック画面/通知に再生コントロール表示 |
| F5 | 再生速度変更 | 0.5〜3.0倍（0.1刻み、ピッチ維持）。プレイヤー側で変速 |
| F6 | 章選択 | EPUBの目次（nav/NCX）から章一覧を表示し、任意の章へジャンプ |
| F7 | 章内シーク | スクロールバーで章内の任意位置（文チャンク単位）へジャンプ。ドラッグ中はその位置の本文プレビューを表示 |
| F8 | 音声キャッシュ | 合成済み音声を (本, 章, チャンク, 話者) キーで永続キャッシュ。キャッシュヒット時はAPIを叩かない |
| F9 | 先読み合成 | 再生中、常に3〜5チャンク先まで裏で合成しておく（途切れ防止） |

|---|---|---|

## 4. 技術仕様

### 4.1 EPUB解析パイプライン

```
EPUB(zip)
 → META-INF/container.xml → OPFパス取得
 → OPF: メタデータ(書名/著者/カバー) + spine(本文ファイル順序)
 → nav.xhtml または toc.ncx → 章タイトルと本文ファイルの対応（目次）
 → 各XHTML: タグ除去して本文テキスト抽出
     - ruby要素: 基本は漢字(ベース)を採用。誤読が多ければrt(ふりがな)優先を設定で切替
     - 画像・脚注・目次ページ等はスキップ
 → 文分割: 「。」「！」「？」「』」「」」等で区切り、
    連結して 50〜200文字程度の「チャンク」を生成（これが合成・シークの最小単位）
```

### 4.2 データモデル

```
Book     { id, title, author, coverImage, importedAt, speakerId, lastPosition }
Chapter  { bookId, index, title, charCount }
Chunk    { bookId, chapterIndex, index, text, charOffset }
AudioCache { bookId, chapterIndex, chunkIndex, speakerId, filePath, durationMs }
Position { bookId, chapterIndex, chunkIndex }   // 再生位置の永続化
```

### 4.3 再生エンジン

- チャンク列を順次再生するキュー方式。再生中に先読みワーカーが3〜5個先まで合成
- チャンク境界の無音ギャップを最小化（次チャンクをプリロードして即時切替）
- シークバーの目盛りは「文字数ベースの推定時間」（未合成部分は 約6文字/秒 で推定し、合成済み分は実測値で補正）
- 変速はプレイヤーのplaybackRate（ピッチ補正あり）で実現

### 4.4 エラー処理

| ケース | 挙動 |
|---|---|
| ポイント不足 (`notEnoughPoints`) | 再生を一時停止し「本日の上限に達しました（残り◯時間でリセット）」表示。キャッシュ済み範囲は再生可 |
| ネットワークエラー | 3回リトライ→失敗なら一時停止して通知。キャッシュ済み範囲はオフラインでも再生可 |
| 合成失敗 (`failed`) | 該当チャンクをスキップして次へ（記号だけの行などで起こりうる） |
| EPUB解析失敗 | 取り込み時にエラー表示（DRM付きEPUBは解析不可の旨を案内） |

## 5. 画面構成

```
[ライブラリ] ──タップ──> [プレイヤー] ──目次ボタン──> [章リスト(モーダル)]
     │                        │
     └─ [＋]取り込み           └─ 歯車 ──> [設定]
```

1. **ライブラリ**: 本のグリッド表示（カバー/書名/進捗%）、＋ボタンでEPUB選択、長押しで削除
2. **プレイヤー**: カバー、書名/章名、現在読み上げ中の文、章内シークバー、再生コントロール（1文戻る/再生停止/1文進む、前章/次章）、速度ボタン、目次ボタン
3. **章リスト**: 章タイトル一覧、現在章のハイライト、章ごとのキャッシュ済みマーク
4. **設定**: 話者選択（試聴つき）、既定速度、キャッシュ使用量とクリア、API残ポイント

画面モックは別途チャットに提示。

## 6. 未決定事項（ゴーサイン前に決めること）

1. **プラットフォーム**（最重要。実装技術がここで決まる）
   - a. Webアプリ(PWA): 開発が最速、PC/スマホ両対応。ただしiPhoneでのバックグラウンド再生・ロック画面操作に制約あり
   - b. iOSネイティブ(SwiftUI): バックグラウンド再生が最も確実。Mac環境ありなので開発可。実機に入れるには無料枠(7日更新)かApple Developer登録($99/年)
   - c. Flutter: iOS/Android両対応でバックグラウンド再生も安定（audio_service）。開発規模はやや大きめ
2. 既定の話者（ずんだもん等。アプリ内で変更可能にするのでデフォルトだけ決める）
3. MVPの範囲が §3.1 の通りでよいか
